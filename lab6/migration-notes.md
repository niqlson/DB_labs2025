# Migration Notes (Lab 6)

This document tracks every Liquibase change set that replaces the Prisma-driven workflow from the spec. All migrations are pure SQL change logs executed through Liquibase.

## 001-baseline-schema (`lab6:001-baseline-schema`)
- Source: `liquibase/changelog/migrations/001-baseline-schema.sql`
- Purpose: import the normalized schema from lab5 (`users`, `products`, ordering tables, etc.) and seed the lookup tables (roles, delivery/payment/status dictionaries).
- Notes: runs once to create the foundation. It contains the `DROP IF EXISTS` guards from lab5 so the change set can be reapplied on an empty database if needed.

## 002-create-product-media (`lab6:002-create-product-media`, `lab6:002-create-product-media-indexes`)
- Source: `liquibase/changelog/migrations/002-create-product-media.sql`
- Changes: adds a dedicated `product_media` table plus indexes so products can store multiple image URLs, tracks whether an asset is primary and keeps a stable display order.
- Rollback: drops the indexes and the table.
- Sample SQL fragment:
  ```sql
  CREATE TABLE product_media (
      id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      product_id BIGINT NOT NULL,
      url VARCHAR NOT NULL,
      alt_text VARCHAR,
      is_primary BOOLEAN NOT NULL DEFAULT FALSE,
      sort_order INT NOT NULL DEFAULT 0,
      created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
      CONSTRAINT product_media_product_fk FOREIGN KEY (product_id) REFERENCES products (id)
  );
  ```

## 003-add-allow-preorder (`lab6:003-add-allow-preorder`)
- Source: `liquibase/changelog/migrations/003-add-allow-preorder.sql`
- Changes: augments `products` with `allow_preorder BOOLEAN NOT NULL DEFAULT FALSE` plus a column comment so the storefront can keep selling temporarily unavailable catalog items.
- Rollback: drops the column.

## 004-migrate-image-url (`lab6:004-copy-images-to-media`, `lab6:004-drop-product-image-url`)
- Source: `liquibase/changelog/migrations/004-migrate-image-url.sql`
- Changes: copies legacy `products.image_url` data into `product_media` as primary assets and then drops the obsolete column. This aligns the schema with the new multi-image model.
- Rollback: removes the auto-generated media rows and recreates the legacy column (empty, because data cannot be recovered after the drop).

## 005-refresh-order-totals-view (`lab6:005-refresh-order-totals-view`)
- Source: `liquibase/changelog/migrations/005-refresh-order-totals-view.sql`
- Changes: drops the legacy `order_totals` view and recreates it so the merchandise column name/definition matches the updated schema while still surfacing `grand_total`.
- Rollback: drops the recreated view (baseline change set can restore the previous definition if required).
